# phix 网页端 · 交接文档

> phix 官网（`phix.ing`）：产品页、下载页、账号，以及 **PHL 网页版 `/app/`**（浏览器里的启动器）。
> 仓库：`D:\phix\website`　部署：局域网 `192.168.5.41` 的 systemd 单元 + Cloudflare
> 本文最后核对：2026-10-12

---

## 1. 这条线负责什么、不负责什么

**负责**：`D:\phix\website` 这个站点 —— 官网页面、下载页、账号登录/注册、
**PHL 网页端（`/app/`）**、以及 phix API 的前置代理。

**不负责**（都是别的线）：

- **phix 服务端本身**：`D:\phix\server`（Django，端口 8931）。
  这个站点只是把它**代理**出去（`/api/*` 字节透传），不含业务逻辑。
- **心履网页端**：`D:\moodsite\web`。
- **PHL / PHL Lite / 心履各客户端**：各自仓库。

**架构上要和心履网页端区分清楚**：

| | phix 网页端 | 心履网页端 |
|---|---|---|
| 形态 | **客户端 SPA**（`static/app/app.js` 在浏览器里跑） | **服务端渲染**（Django 读库出 HTML） |
| 数据 | 通过本站的 `/proxy/*` 走 phix 云同步 | 直接读自己的数据库 |
| 技术栈 | Python 标准库 + 原生 JS，**零第三方依赖** | Django + 模板 |

- 站点跑在局域网 **`192.168.5.41`**（systemd 单元，端口 **8940**），

## 4. 本地怎么跑 / 怎么测

测试是**脚本式**的（`check(name, cond)` + 编号），**需要一个跑着的本地站点**：

```powershell
# 1) 起一个本地站点（另开一个窗口）
cd D:\phix\website
D:\phix\server\.venv\Scripts\python.exe -X utf8 server.py --port 8940

# 2) 跑测试（从 D:\phix\website 下）
cd D:\phix\website
$py = "D:\phix\server\.venv\Scripts\python.exe"
foreach ($t in "test_copy_c.py","test_download_page.py","test_phix_site.py","test_docs_page.py",
               "test_deco_pages.py","test_products_page.py","test_products_copy.py",
               "test_log_page.py","test_legacy_login.py","test_app_web.py","smoke.py") {
  & $py -X utf8 $t
}
```

当前各项都是 **0 失败**（`test_app_web.py` 274 项、`test_copy_c.py` 56、
`test_download_page.py` 19、`smoke.py` 26，其余各几十项）。

> **注意**：`smoke.py` 与 `/app/` 相关的用例会**真的打后端**（本机 8931 的 phix）。
> 本地没起 phix 时它们会报 502 `proxy_error`，那是环境问题不是回归 ——
> 但别把它当成"通过"。要完整验证就先起一个本地 phix：
> `cd D:\phix\server ; .venv\Scripts\python.exe -X utf8 run_local.py`。

## 5. 部署与运维

```powershell
cd D:\phix\website
D:\phix\server\.venv\Scripts\python.exe -X utf8 deploy.py
```

它会上传整棵树（排除 `media/logs`、`local-bridge` 等）、装 systemd 单元、重启、并自检：
比对 `/media/downloads/` 每个包的大小、真下一个小包算 md5、逐字节比对。

### 两条**必须知道**的坑

**① 上传的"跳过"判据必须是内容哈希，不能只看大小。**

`deploy.py` 早期版本对大于 4 MiB 的文件只比大小就跳过。2026-10-12 就因此出过事故：
心履 Windows 的 1.1.9 与 1.1.10 安装包**恰好都是 77,877,248 字节**，新包被静默跳过 →
**官网继续发旧安装包，而下载页已经写着新版本号**。
现在已改成一律比内容哈希（大文件只是慢一点，比发错包便宜）。
**不要为了"快一点"把这条改回去。**

**② 页面上的 `?v=` 是服务端注入的，不是模板里写的。**

站点在返回 HTML 时会给静态资源与下载链接**注入 `?v=<内容哈希>`** 穿透 Cloudflare 缓存
（稳定文件名不加这个会一直命中旧缓存）。所以**拿线上页面和本地模板逐字节比是对不上的**，
要比就比"去掉 `?v=` 之后"的内容，或者直接比源站。

另外 Cloudflare 还会在边缘做：邮箱混淆（换成 `/cdn-cgi/l/email-protection` 并注入
`email-decode.min.js`）、注入 analytics beacon、替换 `{{cms:...}}` 占位符。
**源站（局域网 8940）看到的才是我们真正上传的那份。**

### 发版时下载页要怎么更新

下载页的版本号 / MB / 字节数 / 日期 / `checksums.txt` 由
`D:\phix\_recon\update_download_page.py --apply` 统一处理（它按文件名定位到卡片，
每改一处都断言真的改到了）。**不要手工改这些页面**——以前就是因为只改了版本号、
没改 MB 数字，页面上出现过"163.9 MB（172,214,729 字节）"这种自相矛盾的东西。

## 6. 调用的服务端接口

这个站点自己**不是** API 服务端，它是 phix API 的**前置**。两条代理路径要分清：

| 路径 | 做什么 |
|---|---|
| `/api/*`、`/healthz` | **字节透传**到 phix 服务端（`_proxy_to_phix`）。这一层看不懂内容 |
| `/proxy/*` | **带会话**的代理：从签名 cookie 取令牌与 DEK，替浏览器做端到端加解密 |

`/app/` 里的 SPA 走的是 `/proxy/sync/objects/<name>/`（读写同步对象、服务端代解密），
以及 **`/proxy/sync/watch/`（长轮询）**。

### 两条容易踩的接口规矩

**① 查询串要放进信封的 `q` 字段，不能拼进 path。**
信封的 AAD 是「方法 + 路径」，**不含查询串**。把它拼进 path 会让两边算出的 AAD 不一致，
响应直接解不开。所以 `_phix_request` 有独立的 `query` 参数。

**② 长轮询的转发超时必须大于服务端的挂起时间。**
服务端挂 25 秒，这里转发给 40 秒；浏览器侧给 45 秒。
给短了会在服务端刚要返回时被掐断，表现成一串"假失败"。

协议权威文档：`D:\phix\server\docs\协议规范.md`、`D:\phix\server\docs\同步实时化.md`。

## 7. 用户数据与登录态

- 登录态是一个**签名的 cookie**，里面装着 access/refresh 令牌**以及 DEK**
  （端到端加密的密钥）。服务端**不落明文**，DEK 只在处理这一个请求时用到。
- 免密（SSO）会话还没解锁时手里没有 DEK —— 这时写同步对象会被明确拒绝
  （`dek_locked`），**宁可报错也不把明文写进一个本该端到端加密的对象里**。
- 管理后台在 `/admin/*`，只看 `is_staff`。
- 站点内容里可编辑的文案用 `{{cms:键|默认值}}` 占位，实际值存在后台。

## 8. 开发思路与约定

- **零第三方依赖**（除 `cryptography`）：服务端只用标准库。加依赖前先想清楚。
- **测试是脚本式的**：`check(name, cond, extra)` 累加通过/失败项，最后打印
  「通过 N 项，失败 M 项」。断言"代码里**不能**出现某个 token"时要用
  `strip_comments()` 先剥注释 —— 注释里常常正是"不要这么写"的说明。
- **注释和提交信息用中文**，写**为什么**；`server.py` 里到处是"为什么这条路由必须排在
  那条前面"的说明，照着做。
- **`static/app/app.js` 有两条被测试强制的约束**：
  字符串 `PHL` 恰好出现 **3 次**、且**不能出现「心履」**。加文案时注意。
- **写盘用临时文件 + rename**；页面模板改动后**必须重启服务**（Python 服务不热加载）。
- 站点对**默认 urllib User-Agent** 会 403（Cloudflare）—— 写探测脚本要带浏览器 UA。

## 9. 已知的坑与禁忌

1. **部署的跳过判据不能只看大小**（§5 ①）。
2. **别手工改下载页的版本/大小**，用统一脚本（§5）。
3. **路由顺序**：`/app/mail/<uid>/` 会吞掉 `contacts` 这类固定路径段，
   所以 `/app/mail/contacts/` 必须排在它**前面**（`server.py` 里有大段注释）。
4. **查询串进信封的 `q`，不进 path**（§6 ①）。
5. **`app.js` 的 `PHL` 计数约束**（§8）。
6. **模板改完要重启**服务，否则一直发旧页面。
7. **Cloudflare 会改写页面**，别拿线上页面直接和本地模板做字节比对（§5 ②）。
8. 写 PowerShell 脚本要**带 UTF-8 BOM**。
